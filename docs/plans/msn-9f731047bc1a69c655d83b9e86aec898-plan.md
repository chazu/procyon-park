# Mission Plan

Mission: `msn-9f731047bc1a69c655d83b9e86aec898` — Mission-panel epic/story tree
Repo: procyon-park

## Intent

Give operators at-a-glance visibility into mission decomposition. On the dashboard
Missions panel, each **non-archived** mission card should render its epic and the
epic's child stories as an **indented tree**, so an operator can see the shape and
progress of a mission's work (story **title**, **status**, **wave**) without leaving
the Missions panel or opening another view. The tree is built purely from data the
DashboardSSE tick snapshot already caches — no new scans, no new SSE channel.

## Success Criteria

- For every non-archived mission (awaiting-approval and other/decided/approved
  states) whose `payload.epic_id` references an epic, the rendered Missions-panel
  HTML contains an indented tree beneath the mission card listing the epic and its
  child stories.
- Each story row renders three fields: **title**, **status**, **wave**.
- The tree is built ENTIRELY from the already-cached per-tick snapshot
  (`snap at: 'missions'` and `snap at: 'workitems'`, both already produced by
  `computeSnapshot`). No new `bbs scanAll:` / per-tick scan is added; no new SSE
  channel/event is introduced.
- Every user-controlled field (story title/status/wave, epic title/id, mission
  fields) passes through `htmlEscape:` — a story titled with a literal `<script>`
  renders escaped, not executed.
- A new render test in `test/api/test_mission_panel.mag` seeds a mission + epic +
  child stories into the snapshot input and asserts the rendered HTML contains the
  indented story rows with title/status/wave, deterministic wave-then-identity
  ordering, `<script>` escaping, and that an **archived** mission gets **no** tree.
- Archived missions do NOT gain the tree (they stay in the collapsed Archived
  section unchanged).
- Existing `test_mission_panel.mag` cases and the rest of the suite still pass;
  `mag build` stays green.

## Research Synthesis

The scout research (`docs/scout/mission-panel-epic-story-tree.md`) was reviewed
adversarially and returned a **SOUND (pass)** verdict; all file/method/line
citations were verified accurate. Established facts, with the reviewer's
corrections folded in:

- **Data model verified.** Mission `payload.epic_id = 'epic-' + mid`
  (`Dispatcher.mag:693,730`). The **epic** workitem has `identity = epic_id`,
  `type = 'epic'`, `parent = nil`. Each **story** workitem has
  `identity = 'story-'+mid+'-'+idx`, `type = 'story'`, `parent = epic_id`, and
  integer `wave` via `missionWaveOf:` (`Dispatcher.mag:761–769`). Awaiting-approval
  missions may not have an `epic_id` yet — those simply render as they do today.
- **Zero new scans.** `snap at: 'workitems'` is the whole cached workitem array
  (already scanned once for the Kanban board). The mission→epic→story association
  is a pure in-memory filter: epic = `workitems detect: identity = epic_id`;
  stories = `workitems select: parent = epic_id`. This honors the pp-serve
  RSS-runaway constraint.
- **Reviewer correction — epic root is NOT in the story filter.** The epic has
  `parent = nil`, so the `parent = epic_id` filter returns only stories. The epic
  root must be looked up separately by `identity = epic_id`, and its **absence must
  be guarded** (missions whose epic workitem is missing render without a tree).
- **Reviewer correction — archived gating is by loop, not by flag.** Both the
  `others` loop and the `archived` loop call `renderMissionCard: … awaiting: false`,
  so the `awaiting` flag cannot gate the tree. The tree must be appended only in the
  awaiting loop and the others loop, and **never** in the archived loop.
- **Reviewer correction — wave sort is NUMERIC.** Story `wave` is an INTEGER, not a
  string. `sortStories:` must compare wave **numerically**, then tie-break on
  identity lexicographically (deterministic, byte-stable — acceptable per the
  success criteria even though `story-<mid>-10` sorts before `story-<mid>-2`). A
  malformed / non-integer wave must be guarded so the comparator can't throw.
- **Determinism is the highest risk.** `sendElements:to:key:` byte-compares the
  whole `missionsHtml` per subscriber; any diff triggers a wholesale `outerHTML`
  replace that resets scroll and collapses open `<details>`. `scanAll:` bucket order
  is not tick-stable, so story rows MUST render in a deterministic total order or
  the panel churns every tick.
- **Escaping is safe for non-strings.** `htmlEscape:` does `asString` and maps
  `nil -> ''`, so the integer `wave` and any missing field pass through safely — run
  every field through it, no `printString`, no nil guard.
- **Maggie discipline.** Never chain `and:` (`a and:[b] and:[c]` → `and:and:`
  doesNotUnderstand); nest instead. Preserve the existing per-mission and per-card
  `on: Exception` guards so a malformed epic/story tuple is skipped without breaking
  the panel (MP2 already asserts this — must not regress).
- **Reviewer correction — no CSS.** `static/dashboard.html` is out of scope, so no
  styling can be added. New `mission-tree` / `mission-story` classes render as an
  **unstyled nested list**; "indented tree" relies on default browser list
  indentation only. No collapsible / styled visuals are promised.
- **CHANGELOG scope reconciliation.** Mission Out-of-Scope names only
  `DashboardSSE.mag` + its test, but repo CONVENTIONS require a `CHANGELOG.md`
  `[Unreleased]` entry in the same commit. This plan **explicitly sanctions
  `CHANGELOG.md` as the one allowed third-file touch**; it is a conventions
  artifact, not a functional source change, and does not create a same-file wave
  conflict.
- **Test-runner registration.** New `Test*` classes are silently skipped unless
  registered in the runner invocation block at the bottom of the file. A
  `seedStory:`/`seedWorkitem:` helper must be added (none exists;
  `seedMissionWithEpic:` only stamps `epic_id` and creates no workitems).

## Proposed Approach

Extend `renderMissionsHtml:` in `src/api/DashboardSSE.mag` to append a
server-rendered, deterministic epic/story tree beneath each non-archived mission
card, built entirely from the cached snapshot:

1. Add a `renderMissionTree: m workitems: wis` helper that resolves the epic by
   `identity = m.payload.epic_id`, filters child stories by `parent = epic_id`,
   sorts them via a new numeric-wave `sortStories:` comparator, and emits a nested
   `<ul class="mission-tree">` with one `<li class="mission-story">` per story
   showing `htmlEscape:`-d title / status / wave. Guard missing `epic_id`, missing
   epic workitem, and malformed rows; wrap in `on: Exception`.
2. Call `renderMissionTree:workitems:` immediately after the card in the
   **awaiting** loop and the **others** loop only — never the archived loop —
   threading the cached `workitems` array through from `renderMissionsHtml:`.
3. Add `sortStories:` mirroring `sortMissions:` but comparing `wave` numerically
   with an identity lexicographic tie-break and a non-integer-wave guard.
4. Add a `seedStory:`/`seedWorkitem:` test helper and a new `MP9` render test in
   `test/api/test_mission_panel.mag` covering: tree markup present, title/status/
   wave per row, wave-then-identity ordering, `<script>` escaping, and
   archived-mission tree SUPPRESSION. Register the class in the runner.
5. Add a `CHANGELOG.md` `[Unreleased]` entry and a conventional-commit message.

Because every change lands in `DashboardSSE.mag` (+ its test, + the CHANGELOG
conventions artifact), this is delivered as **exactly ONE story** — the mission's
hard scope-of-touch constraint that prevents same-file wave conflicts.

## Risks

- **Panel churn / scroll reset (highest).** Non-deterministic story order breaks
  `sendElements:to:key:` change-detection. *Mitigation:* numeric-wave +
  identity-lexicographic total order in `sortStories:`; MP9 asserts ordering; verify
  byte-stable HTML tick-to-tick when unchanged.
- **Archived leakage.** Gating on the `awaiting` flag would wrongly show trees on
  archived cards. *Mitigation:* gate by loop (append only in awaiting + others
  loops); MP9 asserts archived missions emit no tree markup.
- **Epic-root absence.** Epic has `parent=nil` and may be missing.
  *Mitigation:* look up epic by identity separately and guard its absence; render no
  tree rather than throw.
- **XSS via story fields.** *Mitigation:* every field through `htmlEscape:`; MP9
  asserts a `<script>` title renders escaped with no raw `<script>` surviving.
- **Comparator throw on malformed wave.** *Mitigation:* non-integer-wave guard in
  `sortStories:`; per-mission/per-card `on: Exception` guards preserved (MP2 must
  not regress).
- **CHANGELOG flagged as out-of-scope by reconciler/lint.** *Mitigation:* plan
  explicitly sanctions `CHANGELOG.md` as the single allowed conventions third-file;
  implementer confirms lint tolerance.
- **Maggie `and:` chaining footgun.** *Mitigation:* nest all compound predicates;
  no chained `and:`.
- **No CSS available.** Tree renders as an unstyled nested list. *Accepted* — visual
  polish is out of scope; default browser list indentation satisfies "indented".

## Definition of Done

- Non-archived missions with an `epic_id` render an indented epic/story tree with

  scans/channels).
- Archived missions render no tree; missions without an epic render unchanged.
- All user-controlled fields are HTML-escaped.
- `MP9` render test (ordering + escaping + archived-suppression) passes; the full
  `test_mission_panel.mag` suite and the rest of the test suite pass; `mag build`
  green.
- `CHANGELOG.md [Unreleased]` updated in the same commit; conventional-commit
  message; no source file other than `src/api/DashboardSSE.mag` (+ its test +
  CHANGELOG) changed.
